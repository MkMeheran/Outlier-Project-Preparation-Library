# Outlier Project Preparation Library

A community-maintained study library for people preparing for AI-training and evaluation projects associated with Outlier. The goal is practical: explain the workflow, turn webinars into searchable notes, collect examples, and document common platform problems without making readers watch an entire meeting again.

> **Important:** This is an independent contributor resource, not an official Outlier publication. Project names, task availability, onboarding steps, quality rules, and platform interfaces can change. Always follow the current instructions shown in your own Outlier account and the official project team.

## Start here

1. Read [Aether: project orientation](Aether/README.md) for the terminology and workflow.
2. Open the [Omni TTS ELO webinar notes](Aether/Webinars/2026-10-16-omni-tts-elo/README.md) for the October 2026 session summary, rating dimensions, examples, Q&A, and chat references.
3. Use the [troubleshooting guide](Aether/Guides/troubleshooting.md) when a task is missing, audio will not load, or the rating controls do not appear.
4. Review [community research](Aether/Research/community-reports.md) for public contributor reports and what can—and cannot—be concluded from them.

## How to use these notes

- **Learn:** Read the concepts and workflow before attempting a task.
- **Practise:** Use the examples as reasoning exercises, not as answer keys for live assessments.
- **Check:** Compare your judgement against the current task instructions. A webinar summary cannot replace the live rubric.
- **Troubleshoot:** Record the exact error, time, task type, and steps already tried. Do not post account IDs, task IDs, private screenshots, or personal information publicly.
- **Contribute:** Submit corrections or new notes with a source date and a clear label: `Webinar`, `Official project update`, `Contributor report`, or `Independent interpretation`.

## Evidence labels

| Label | Meaning |
|---|---|
| **Webinar note** | Paraphrased from the meeting transcript supplied for this guide. |
| **Public contributor report** | A person’s experience posted publicly; useful as a signal, not proof of a universal rule. |
| **Practical interpretation** | A suggested way to apply the guidance or investigate a problem. |
| **Unverified** | Plausible, but not confirmed by an official project representative or current documentation. |

## Privacy, confidentiality, and responsible sharing

Before making this repository public, remove personal names, email addresses, contributor IDs, task IDs, private Zoom links, internal screenshots, and anything the project rules prohibit sharing. Do not upload full internal guideline PDFs, client data, assessment answers, or confidential task content unless the project explicitly permits public redistribution. These notes intentionally summarize the meeting rather than reproduce a raw transcript. If you are unsure whether a detail is shareable, leave it out and link to an official public source instead.

## Naming ideas

The clearest name is **Outlier Project Preparation Library**. Other options:

- `Outlier-Project-Field-Notes` — practical, experience-based notes.
- `Aether-Task-Prep` — focused on Aether, but less suitable if the repository grows to other projects.
- `AI-Training-Project-Notes` — broad and less tied to one company.

**Recommendation:** keep the repository name `Outlier-project` if you prefer it, but use a descriptive subtitle in the README so visitors immediately understand that it is an independent preparation resource.
